# Filo Fino — единая дизайн-система 2026

Обязательный стандарт вместе с [SEO_ARCHITECTURE_2026.md](SEO_ARCHITECTURE_2026.md).
Версия 16.10.2026. Основа — утверждённая «La línea del filo» и актуальная главная.
Это фиксация существующего языка, не новый дизайн и не новый framework.

## Общие компоненты

Header и Footer: `design-system/components/header.html` и `footer.html`.
Команда `python design-system/render_components.py` записывает их во все разработанные HTML-страницы из seo/routes.json;
`--check` проверяет отсутствие расхождения. Компоненты доступны без JavaScript.
Header имеет единые логотип, кнопку меню, размеры, отступы и структуру. Содержимое
desktop-nav контекстное: разделы мастерской на home, разделы услуги на странице ножей.
Не создавать отдельные версии визуального header или независимые футеры услуг.

Footer полностью общий: логотип, телефон, общий WhatsApp, услуги, блог, адрес,
расписание, Instagram и legal. Меняются только относительные пути к главной/ножам.
Изменение шаблона применяется ко всем страницам. Часы не выдумывать: используется
существующее расписание; известная необходимость подтверждения перед production
остаётся в SEO-стандарте. В меню/hero допустим контекстный WhatsApp.

## Токены и типографика

Токены объявлены в `design-premium-preview/premium.css`, не дублировать их в услугах.

| Токен | Значение / назначение |
|---|---|
| `--ink` | `#182024`, основной графит |
| `--deep` | `#111719`, глубокий фон |
| `--panel` | `#273237`, поверхности |
| `--steel` | `#a9bbc3`, вторичный акцент |
| `--paper` | `#f0efe8`, основной светлый текст/секции |
| `--brass` | `#e8be82`, действия и акценты |
| `--line` | `#455157`, разделители |
| `--display` | локальный Barlow 600, заголовки/логотип |

Основной мобильный текст 16 px, line-height 1.65–1.8; подписи 12–14 px.
H1 видим в HTML, единственный; текст и иерархию не менять ради размера.
Главная сохраняет масштабный брендовый H1. Услуга использует компактный display:
44–58 px mobile, 68–106 px desktop. Переносы обычных слов естественные; без
обрезания текста/ellipsis. Для карточек — адаптивный размер по ширине сетки.

## Hero

Обе страницы используют `.hero`, `.hero-photo`, `.hero-content`, `.hero-actions`.
Фото — настоящий img с alt/размерами и high fetchpriority, позиционированное внутри
фоновой композиции; диагональное кадрирование и те же градиенты читаемости.
Не возвращать прямоугольную фото-карточку под H1 на внутренних страницах.
Модификатор `.hero--service` адаптирует длинный H1, breadcrumb и высоту,
не создаёт новый визуальный язык. Сначала услуга/польза и два действия, затем
короткая информация о визите. Высота определяется содержимым, без пустого min-height.
На desktop картинка справа; mobile — справа за верхней частью композиции.
Палитра и интеграция фото наследуются от главной, фотографии не подменяются.

## CTA, SVG и отступы

Hero CTA — две колонки `minmax(0,1.65fr) minmax(0,1fr)`, gap 8 px mobile,
10 px desktop. WhatsApp и Maps не переходят на два отдельных ряда, в том числе
при 320 px. Текст внутри кнопки может переноситься при нехватке места.
Высота от 50 px mobile / 52 px desktop; 13 / 14 px шрифт; brass/outline как прежде.
У прочих компонентов допускается собственная сетка, но сохраняются формы/цвета.
Все переходы — `<a href>`, действия интерфейса — button/details; видимый focus.
SVG единым outline-стилем, обычная толщина 1.5, размеры иконок 17–22 px;
никаких emoji/текстовых стрелок, в том числе CSS content. Декоративные SVG aria-hidden.

Горизонтальные gutters `.section-shell`: `clamp(20px,5vw,84px)`.
Рабочие интервалы 8/12/16/24/32/48 px; у широких секций прежние desktop-отступы.
Не переопределять общую высоту header или сетку Hero в CSS отдельной услуги.

## Сетки и композиция

Главная сохраняет асимметрию: большая карточка ножей и две компактные карточки.
Desktop — большая слева на две строки, две справа. Mobile — большая на всю ширину,
две компактные снизу в двух колонках. Фото и содержимое текущих карточек сохраняются.
Три существующих touch-hand перенесены только на основные `.service-link`;
их paths/rings и стиль неизменны. Только один палец сверху справа вместо круглой
стрелки, pointer-events:none; названия снизу. Не дублировать руки в shortcuts.
Shortcuts главной — отдельная сетка 1+2: первая ссылка на всю ширину, две равные
снизу, единые отступы/типографика и полная кликабельность. Не смешивать с service cards.

Навигация ножей: desktop три компактные колонки в контейнере до 1100 px.
Mobile — первая ссылка span 2, следующие две в равных колонках; gap 8 px.
`minmax(0,1fr)`, label min-width:0, SVG flex-shrink:0, никакого absolute поверх текста.
Вся карточка кликабельна. Проверять 320/360/390/425–430 px и desktop.
Основное содержимое услуг самостоятельное; не копировать секции home механически.

## Контакты и движение

Использовать общий `.address-study`: адресная графическая композиция со ссылкой на
Google Maps, не утверждение точной географии улиц. Адрес, часы и телефон в обычном
HTML; WhatsApp и маршрут — доступные параллельные действия.

Анимации — progressive enhancement: текст видим без JS. Общий Hero: 650 ms для H1,
750 ms для фото, transform/opacity. Scroll reveal — IntersectionObserver без
постоянных scroll-handler и layout reads. Руки пульсируют с паузой при видимости
самих service cards: два кольца, повтор 3.8 s с паузой, сдвиг второго 0.35 s.
`prefers-reduced-motion` отключает пульсацию/анимации;
не менять форму подсказок. Не добавлять библиотеки ради этих эффектов.

## Проверки и порядок стилей

Порядок: premium.css → refinement.css → seo.css (home) / knives.css (услуга).
Общие компоненты и hero/jump-сетки живут в refinement.css; knives.css содержит
только специфические секции. Не добавлять конкурирующие page overrides общих правил.
Перед PR: render_components --check, seo/verify.py, seo/verify-interactions.cjs,
design-system/verify.cjs. SEO-метаданные/реестр/миграция проверяются на сохранение.
Медиа сравниваются побайтно. После preview — HTTP/хеши ресурсов и deployment status.

Ограничение текущего прогона: Chromium не запускается до рендера. DOM/CSS-contract
проверки размеров не являются фактическими screenshots, Safari или Lighthouse.
Перед production обязательна отдельная реальная визуальная проверка 320–1440 px,
keyboard, no-JS, reduced motion. Не объявлять эти проверки пройденными без выполнения.
