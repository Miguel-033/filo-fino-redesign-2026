# Критерии будущего прототипа

Это предлагаемые условия проверки после отдельного задания на разработку. Здесь нет готового UI, установленного пакета или результатов Lighthouse.

## Mobile-first и доступность

- Проверить 320, 360, 390 и 430 CSS px, landscape, 200% масштаб текста, длинные испанские названия и системные safe areas. Вертикальная прокрутка остаётся браузерной; pinch zoom не отключать.
- На главной три основных маршрута можно обнаружить без swipe и открытия modal. Secondary услуги не теряются: текущие машинные ножи требуют отдельного доступного маршрута.
- Проектная цель для основных controls — 44–48 CSS px и примерно 8 px между небольшими кнопками. Не выдавать это за буквальный минимум WCAG 2.2 AA: критерий Target Size Minimum имеет размер 24×24 CSS px и исключения. Проверить фактические controls, а не только номинальные размеры иконок.
- Для всех действий — настоящие button, для переходов — a. Доступные имена, focus-visible, логичный порядок Tab и heading hierarchy. Текст на фотографиях проверять для каждого снимка; цвет не единственный способ различать услуги.
- Drawer: accessible name, начальный фокус, inert background, Escape, видимая close-кнопка, focus return. Drawer scroll не должен уводить background; закрытие не сбрасывает исходную позицию страницы. Проверить browser Back явно.
- «До/после»: labels, клавиатура и tap-кнопки выбора состояния. Обычная пара изображений — fallback. Drag не является единственным средством получить информацию; вертикальный page scroll сохраняется.
- Галерея: visible close и prev/next, описания, keyboard/screen reader, восстановление фокуса; не открывать fullscreen автоматически. Встроенные подписи PhotoSwipe v5 не считать готовыми без дополнительного решения.
- `prefers-reduced-motion`: сразу конечное состояние, без появления текста по буквам, blur, больших перелётов, parallax и autoplay. Ошибка JS не делает контент невидимым.

Основа — прочитанный локальный UI/UX Quick Reference и [свежие Vercel Web Interface Guidelines](https://github.com/vercel-labs/web-interface-guidelines/blob/main/command.md). Новые commandfor, closedby, scroll-driven CSS и View Transitions нельзя делать обязательными без проверки поддержки. [MDN dialog](https://developer.mozilla.org/en-US/docs/Web/HTML/Reference/Elements/dialog) различает зрелую поддержку элемента и поддержку отдельных новых возможностей.

## Политика анимации

Один выразительный акцент на странице. Все остальные движения показывают результат действия: открытие меню, нажатие, смену сравнения или gallery. Предложенные длительности — 100–150 ms для press, 180–260 ms для короткого reveal, примерно 200–300 ms для drawer; значения требуют теста на устройстве и корректируются по смыслу.

Приоритет opacity и transform. Не использовать transition-all, постоянный will-change на десятках фотографий, бесконечные RAF loops, анимацию width/height или размывание больших слоёв. Изображения кромки должны быть чёткими. ScrollTrigger pin/scrub, endless carousel и cursor effects не входят в рекомендуемую базу.

IntersectionObserver может дешево отслеживать видимость, но его callbacks выполняются на main thread и должны быть короткими. Измерение layout в каждом callback/scroll tick может уничтожить выигрыш. Уменьшение движений само по себе не заменяет качественные изображения и быстрый response UI.

## Фото и видео

- Только согласованные реальные материалы Filo Fino. Для сравнения — одинаковый инструмент, ракурс, масштаб и свет. Не использовать AI-generated «после», не усиливать эффект фильтром.
- Указанные width/height или aspect-ratio для резервирования места; responsive srcset/sizes, отдельные thumbnails и большие кадры для zoom.
- Ключевой LCP-кадр загружается сразу. Ниже первого экрана — lazy-loading. Формат выбирать по качеству и поддержке, например WebP/AVIF с fallback при необходимости.
- Видео работы — poster и воспроизведение по нажатию, controls/playsinline и содержательная подпись; preload none/metadata по ситуации. Для значимых звуков/речи — captions/transcript. Не помещать autoplay video hero или YouTube iframe в обязательный первый экран.
- Не загружать PhotoSwipe originals, несколько сравнений и видео всех трёх услуг до намерения просмотра. Встроенные CodePen/галерейные iframe в production не нужны.

## Предлагаемый технический бюджет

Цели ниже — авторские ограничения для будущего прототипа, не текущие значения и не стандарт размера сайта.

| Показатель | Предлагаемая цель |
| --- | --- |
| Добавленный interaction JS без gallery | До 20 KB compressed для независимого vanilla-варианта |
| Необязательная gallery/animation dependency | Отдельно измерить; отложить загрузку, если не нужна первому экрану |
| Первый экран: фото | Ориентир 120–200 KB на mobile с сохранением детали инструмента; качество важнее произвольной цифры |
| Необходимые font assets | Не более двух начальных WOFF2 файлов; только нужные subsets/веса |
| Декоративные сторонние scripts | 0 |

Если budget превышен, сначала упростить эффект и изображения, не переходить на более сложный framework. Проверять фактическую сборку и transferred bytes, включая CSS, dependencies, font и decode memory; не складывать маркетинговые размеры модулей как итоговый payload.

В будущем ориентироваться на [Core Web Vitals](https://web.dev/articles/vitals): LCP ≤2.5 s, INP ≤200 ms, CLS ≤0.1 при 75-м перцентиле реальных визитов. Лабораторный запуск не доказывает field percentiles. Эта записка не содержит измерений текущего сайта или источников; никакие показатели эффективности компонентов не сертифицированы.

## WhatsApp и другие контакты

Перенести на будущее не виджет, а обычную ссылку. [Официальный click-to-chat](https://faq.whatsapp.com/5913398998672934) описывает международный номер в wa.me и URL-encoded prefilled message. По официальному индексированному тексту функция работает на телефоне и WhatsApp Web; прямое извлечение текста FAQ дало пустой результат, что отмечено в реестре.

Для страницы конкретной услуги текст сообщения может обозначать инструмент и проблему, без обязательных персональных данных. Это черновик в интерфейсе WhatsApp, не автоматическая отправка. Не добавлять spinner «mensaje enviado» при одном клике: сайт не знает, было ли сообщение отправлено.

Контакт доступен на первом экране и после доказательства/условий; возможную sticky нижнюю панель надо проверить на перекрытие focus, текста, video controls, cookie banner и экранной клавиатуры. Сохранить tel-ссылку и другие согласованные альтернативы. При неработающем JS контакт не исчезает. Для неизвестного устройства не навязывать приложение вместо понятной ссылки.

Не использовать unverified WhatsApp logo из икон-пака как доказательство права на бренд; официальные brand assets имеют свои правила. В исследовании брендовые файлы не копировались. Не открывать контакты и не отправлять сообщения для проверки.

Если в будущем будет разрешена аналитика: клики, переходы и подтверждённые обращения различаются. Текст сообщения, номер клиента и другие личные данные не передаются как event parameters. Эффект sticky CTA или сравнения «до/после» проверяется, а не объявляется гарантированным ростом conversion rate.

## План проверки после разрешения разработки

1. Реальные Safari iOS и Chrome Android, бюджетное устройство и слабая сеть; menu, click-to-chat, image compare, photo zoom, video и Back.
2. Keyboard-only, VoiceOver/TalkBack, 200% text zoom, reduced-motion, без JS; присутствие всех услуг и контактов.
3. Lighthouse/DevTools для лабораторных сценариев, CPU/GPU профиль движения; screen recordings frame drops и память изображений. Затем field CWV, если доступны и разрешены данные.
4. Короткие задачи для представителей трёх аудиторий: найти свою услугу, увидеть доказательство, понять следующий шаг и открыть правильный контакт. Рекрутинг/сообщения требуют отдельного задания.
