# Перспективные решения и способы адаптации

Дата проверки ссылок и лицензий: 14.10.2026. «Низкая/средняя стоимость» — сравнительная инженерная оценка, не замер FPS или размера production bundle. Лицензия кода не распространяется автоматически на фотографии, шрифты, логотипы и встроенные сторонние пакеты.

## R01. Три видимых входа в услуги

**Реальный пример:** [Magic UI Bento Grid](https://magicui.design/docs/components/bento-grid). Исходный компонент [bento-grid.tsx](https://github.com/magicuidesign/magicui/blob/main/apps/www/registry/magicui/bento-grid.tsx) прочитан; это React/TypeScript, CSS Grid через Tailwind, Radix icon и Button-зависимость.

**Лицензия:** MIT для публичного [Magic UI repository](https://github.com/magicuidesign/magicui/blob/main/LICENSE.md); Pro-шаблоны не входят в это утверждение.

**Переносимость:** готовый TSX не работает в статическом HTML напрямую. Идея размещения легко воспроизводится самостоятельно на CSS Grid. Для Filo Fino предлагаются три равноценных маршрута, а не декоративная асимметрия SaaS: ножницы, ножи, маникюр/педикюр. Каждая карточка — фотография, название, короткое описание задачи и видимая ссылка.

**Mobile:** одна колонка; компактная горизонтальная композиция «фото + текст» внутри каждой карточки, чтобы выбор всех трёх направлений не требовал перелистывания carousel. Размер и порядок уточнить на 320–430 px с реальными испанскими словами. Источник использует трёхколоночную grid-базу, col-span и hover-состояния; это не доказательство готовой мобильной адаптации. Все действия должны быть видны без hover.

**Производительность:** низкая у независимой CSS-реализации; основная стоимость — фотографии. React и дополнительные UI-зависимости для одной сетки не оправданы. Не переносить transition-all и вложенные взаимодействия без проверки.

**Выбор:** основной кандидат для главной. Роль карточек — выбор услуги, а не презентация всех возможностей мастерской сразу.

## R02. Фотокарточки с раскрытием / Apple Cards Carousel

**Реальный пример:** [Aceternity Apple Cards Carousel](https://ui.aceternity.com/components/apple-cards-carousel). В опубликованном примере присутствует React hook для outside click и touchstart. Экосистема Aceternity использует React, Tailwind и Motion.

**Лицензия:** опубликована [Aceternity Licence](https://ui.aceternity.com/licence), содержащая собственные условия и запрет распространения исходных Items; страница обозначена Pro. Точная применимость к выбранному free-компоненту отдельно не подтверждена. **Не считать MIT и не копировать код в репозиторий** до установления условий конкретного артефакта. В этой записке используется только ссылка и анализ идеи.

**Переносимость:** TSX нельзя вставить как HTML. Образ крупных фото-карточек можно самостоятельно реализовать на CSS; для реальных работ — scroll-snap или обычная grid. Раскрытие в modal оправдано для подробностей работы, но не должно заменять ссылку на услугу.

**Mobile:** пригодно для вторичной ленты работ, если есть видимые controls и счётчик. Три главные услуги нельзя прятать за горизонтальным swipe. Expanded-card требует close, управления фокусом, нормального возврата и соблюдения safe area.

**Производительность:** средняя у оригинального stack; низкая/средняя у CSS-ленты. Layout transitions и большие изображения повышают стоимость. Отказаться от autoplay и анимации всех карточек одновременно.

**Выбор:** визуальный ориентир для работ, не готовый импорт и не основной selector услуг.

## R03. Материальная фотосетка вместо декоративных эффектов

**Реальные примеры:** [workshop на Land-book](https://land-book.com/websites/59269-workshop), [Dodivetro на Awwwards](https://www.awwwards.com/sites/dodivetro). Land-book указывает Webflow, background images и parallax; Awwwards показывает desktop/mobile, products и gallery elements, но не доказывает конкретный frontend stack Dodivetro. Это референсы ремесленной предметности, не сайты заточки.

**Лицензия:** открытого разрешения на копирование сайта или изображений не установлено. Только вдохновение; использовать собственные фотографии Filo Fino.

**Переносимость:** построить собственные figure/figcaption и CSS Grid; Webflow export и чужой JS не нужны. Для ножниц — видимая рабочая поверхность и результат; для ножей — кромка и характер реза; для маникюра — точность инструмента. Не выдавать сток за выполненную работу.

**Mobile:** одна широкая фотография на карточку, стабильный aspect-ratio, короткая подпись вне изображения. Без hover-зависимых подписей; desktop parallax не переносить на touch автоматически.

**Производительность:** низкая у grid с responsive WebP/AVIF и lazy-loading ниже первого экрана; высокая у неоптимизированных полноразмерных фото и parallax. LCP-фото не lazy-load. Метрики сайтов-источников не измерялись.

**Выбор:** основной принцип фотоматериалов. Анимация не компенсирует отсутствие реального визуального доказательства.

## R04. Боковое мобильное меню на нативном dialog

**Реальные примеры:** [Aceternity Sidebar](https://ui.aceternity.com/components/sidebar) демонстрирует responsive sidebar; [MDN dialog examples](https://developer.mozilla.org/en-US/docs/Web/HTML/Reference/Elements/dialog#examples) — работающий браузерный механизм modal.

**Технология:** HTML dialog, CSS transform/opacity, немного JavaScript для showModal/close. Sidebar Aceternity — React/Tailwind/Motion и dashboard-паттерн, из которого нужен только mobile overlay, не desktop hover expansion.

**Лицензия:** для Aceternity — ограничение R02. Для собственной реализации браузерного API сторонняя runtime-лицензия не требуется; код MDN не копируется, документация имеет собственные условия. Нет необходимости устанавливать библиотеку drawer.

**Переносимость:** полная для самостоятельного dialog. Menu button, nav и links должны быть семантическими. showModal делает фон inert; всё равно проверить имя диалога, начальный фокус и его возврат. Не зависеть исключительно от новых commandfor/closedby без проверки поддержки.

**Mobile:** боковая панель шириной примерно 85–92vw с ограничением на крупных экранах — проектная гипотеза. Отдельные кнопки открытия и закрытия, Escape, скролл длинного меню, безопасные отступы, сохранение позиции страницы. Закрытие после выбора ссылки. Уменьшенный motion — без перелёта. WhatsApp виден внутри меню, но не единственный путь к обращению.

**Производительность:** низкая; ничего не вычислять каждый кадр, не анимировать width и не размывать весь экран. Проверить блокировку фонового скролла и восстановление, а не просто рисовать backdrop.

**Выбор:** основной кандидат для навигации. Поведение browser Back заранее определить и протестировать; не считать его автоматическим следствием dialog.

## R05. Одноразовое лёгкое появление при прокрутке

**Реальный пример:** [Motion inView](https://motion.dev/docs/inview) содержит examples и построен на IntersectionObserver; [Motion animate](https://motion.dev/docs/animate) показывает DOM-анимации.

**Технология / лицензия:** Motion JavaScript — MIT ([LICENSE.md](https://github.com/motiondivision/motion/blob/main/LICENSE.md)), отдельный JS API без обязательного React. Независимый вариант: native IntersectionObserver + CSS opacity/transform, без пакета.

**Переносимость:** полная; source не обязан быть React. Для Filo Fino — только вводный кадр или один блок результатов, а не цепь reveal на каждом заголовке. Весь текст остаётся доступен без JS и при сбое анимации.

**Mobile:** короткое смещение 6–12 px и 180–260 ms — предложенные параметры для теста. При reduced-motion показывать сразу. Не задерживать CTA, цены, название услуги или основной смысл первого экрана.

**Производительность:** низкая для native observer; Motion добавляет библиотеку. Производитель публикует размеры mini animate 2.3kb, hybrid 18kb и inView 0.5kb; это его ориентиры, не замер итоговой сборки Filo Fino и не обещание сетевого объёма. Отписывать observer после одноразового срабатывания; не создавать тяжёлые callbacks.

**Выбор:** native вариант по умолчанию. Motion нужен лишь при нескольких согласованных сложных взаимодействиях.

## R06. Blur Fade как ориентир, с упрощением

**Реальный пример:** [Magic UI Blur Fade](https://magicui.design/docs/components/blur-fade). Прочитанный [blur-fade.tsx](https://github.com/magicuidesign/magicui/blob/main/apps/www/registry/magicui/blur-fade.tsx) импортирует React и motion/react, использует inView и анимацию filter blur.

**Лицензия:** MIT публичного Magic UI repository, не Pro.

**Переносимость:** оригинал требует React/Motion/Tailwind окружения; самостоятельно перенести только идею мягкого появления на R05. Не добавлять этот stack ради одной анимации.

**Mobile:** не анимировать blur текста и больших фото: начало выглядит как нечёткая работа/медленная загрузка. Уменьшенный motion — сразу финальное состояние; никаких длительных stagger delays.

**Производительность:** средняя и потенциально высокая у больших filter-областей; compositor-выгода blur не гарантирована. У варианта opacity + небольшое transform стоимость ниже. Реальная GPU-стоимость демо не измерена.

**Выбор:** условный ориентир; оригинальный blur-эффект не рекомендуется для Filo Fino.

## R07. Lightbox реальных работ — PhotoSwipe

**Реальный пример:** [PhotoSwipe 5.4.4 live gallery](https://photoswipe.com/), [getting started](https://photoswipe.com/getting-started/). Официальная страница показывает touch gallery, responsive images и dynamic import.

**Технология / лицензия:** vanilla JavaScript ES modules + CSS; MIT ([LICENSE](https://github.com/dimsemenov/PhotoSwipe/blob/master/LICENSE)). Пакет не установлен.

**Переносимость:** подходит статическим HTML/CSS/JS; сборщик не обязателен. Базовая grid из обычных ссылок на изображения должна работать без lightbox. Фотографии и подписи размещаются в HTML, а не появляются только после JS.

**Mobile:** touch zoom и свайпы полезны для деталей кромки, но нужны видимые close/prev/next, keyboard alternatives и доступная подпись результата. Captions не входят автоматически в v5 core; обеспечить описание или отдельно проверить caption plugin и его лицензию. Проверить browser Back, возврат фокуса и вертикальный scroll после закрытия.

**Производительность:** средняя добавленная JS/CSS-стоимость, которую можно отложить до намерения открыть работу; responsive srcset для zoom. Не грузить все оригиналы на старте. Самый простой вариант — без lightbox, если деталей немного.

**Выбор:** лучший кандидат из дополнительных gallery-библиотек, если будущий объём работ оправдает его.

## R08. Сравнение «до/после» через input range

**Реальные примеры:** [Stanko: Image Comparison Slider](https://codepen.io/stanko/pen/myddXKm), [mrwweb: Accessible HTML5 Before & After](https://codepen.io/mrwweb/pen/QpKBMM). Во втором опубликованы label, range и подсказка про стрелки; это ориентир, не подтверждённая WCAG-сертификация.

**Технология / лицензия:** HTML input range + CSS clipping + небольшой vanilla JS; public Pens имеют MIT по [официальным правилам CodePen](https://blog.codepen.io/docs/pens/licensing/). При заимствовании сохранить attribution/license; изображения и сторонние ресурсы проверить отдельно. В этой работе код и медиа не копировались.

**Переносимость:** полная. Одна и та же пара фотографий, одинаковый ракурс, масштаб, свет и кадрирование; не симулировать эффект заточки изменением яркости или AI. Для доказательства режущих свойств может быть лучше реальное видео теста — фото кромки показывает не всё.

**Mobile:** видимый handle с большой hit area, подписанные Antes/Después и keyboard управление. Дополнительно кнопки «Antes» / «Después» или обычная пара фото, чтобы drag не был единственным способом. Вертикальную прокрутку страницы не блокировать; тестировать на touch. Range сам по себе не доказывает доступность всего компонента.

**Производительность:** низкая JS-стоимость; две фотографии увеличивают download/decode. Только одна показательная пара на главной, дополнительные — ниже/на странице услуги. Не проводить layout reads при каждом input.

**Выбор:** основной кандидат сравнения без библиотеки, при наличии корректных пар снимков.

## R09. Готовый web component для сравнения

**Реальный пример:** [img-comparison-slider live examples](https://img-comparison-slider.sneas.io/), [repository](https://github.com/sneas/img-comparison-slider).

**Технология / лицензия:** custom element, JavaScript/CSS, MIT ([LICENSE](https://github.com/sneas/img-comparison-slider/blob/master/LICENSE)). Не требует миграции на React.

**Переносимость:** высокая: custom element можно использовать в обычном HTML после подключения его JS. Это всё равно новая зависимость, требующая отдельного будущего решения; сейчас не подключалась.

**Mobile:** автор заявляет mobile-friendly, responsive и accessible. Эти заявления не заменяют тест keyboard, labels, tap alternative, screen reader и конфликта drag/scroll. Дать понятные испанские подписи и fallback двух фото без JS.

**Производительность:** низкая/средняя по архитектуре; точный compressed size и CPU не измерялись. Основная стоимость пары — изображения; не смешивать несколько comparison-библиотек.

**Выбор:** альтернатива R08, если нужен поддерживаемый готовый элемент вместо собственного минимального поведения.

## R10. Compare из Aceternity

**Реальный пример:** [Compare](https://ui.aceternity.com/components/compare): hover и drag modes, optional autoplay; опубликованный default slideMode — hover.

**Технология / лицензия:** React/Tailwind/Motion ecosystem; условия и неопределённость free-artifact — как R02. Не объявлять MIT. Demo-снимки не брать.

**Переносимость:** исходный TSX требует переписывания; для статического сайта R08/R09 проще. Дополнительные sparkles из installation recipe не нужны для демонстрации реальной работы.

**Mobile:** hover-default непригоден для основного touch-взаимодействия. Если вдохновляться, выбирать drag, отключить autoplay и декоративные particles, добавить controls/keyboard alternatives. Никакого сравнения, зависящего от движения курсора.

**Производительность:** средняя/высокая при полном stack и sparkles; низкая у независимого range-варианта. Непрерывный autoplay одновременно отвлекает и расходует ресурсы.

**Выбор:** изученный альтернативный паттерн; не предпочтительная реализация.

## R11. Нажатие кнопки и понятная обратная связь

**Реальный пример:** [Motion JavaScript Press demo](https://examples.motion.dev/js/press), [press documentation](https://motion.dev/docs/press). Документация показывает start/end/cancel и keyboard handling.

**Технология / лицензия:** Motion JS — MIT, см. R05. Минимальный вариант для Filo Fino: CSS active/focus-visible и переход цвета/transform без зависимости. WhatsApp — настоящая ссылка, не div с click-handler.

**Переносимость:** полная; не использовать motion/react ради кнопки. Не превращать ссылки в button только ради эффекта.

**Mobile:** заметное нажатие 100–150 ms и слабое уменьшение масштаба — гипотеза; при reduced-motion оставить изменение цвета. Hit area 44–48 CSS px как проектная цель. Не применять магнитное «убегание» и не делать интерфейс зависимым от hover. Должно быть понятно, что откроется WhatsApp, а сообщение остаётся за пользователем.

**Производительность:** низкая у CSS-состояний; Motion добавляет излишнюю стоимость, если применяется только здесь. Без постоянного пульса, glowing shadow и циклического shimmer.

**Выбор:** обязательный принцип обратной связи, не обязательная библиотека.

## R12. Короткая SVG-анимация / последовательность GSAP

**Реальные примеры:** [GSAP ScrollTrigger examples](https://gsap.com/docs/v3/Plugins/ScrollTrigger/), [DrawSVG examples](https://gsap.com/docs/v3/Plugins/DrawSVGPlugin/). Официальные docs содержат рабочие examples; React не является требованием.

**Технология / лицензия:** vanilla JS, SVG, GSAP core + выбранный plugin. [Standard No Charge GSAP License](https://gsap.com/community/standard-license/) разрешает коммерческие сайты, но это **не MIT**; ограничивает конкурирующие с Webflow инструменты визуального создания анимаций. Filo Fino — сервисный сайт, не такой builder. Перед реальным подключением проверить текущие условия версии и сохранить notices.

**Переносимость:** высокая, но это dependency. Простую линию процесса можно независимо анимировать CSS stroke-dashoffset или не анимировать вовсе. GSAP оправдан только при согласованной последовательности нескольких элементов.

**Mobile:** без pin/scrub, захвата scroll и горизонтальной сцены. Предпочтительно короткая анимация после нажатия «Ver el proceso», с финальным неподвижным видом и текстовыми этапами. Reduced-motion — сразу схема. Не рисовать выдуманное устройство заточки или технологически неверный угол.

**Производительность:** средняя добавленная стоимость GSAP/plugins; SVG рисование может вызывать paint. Выбрать минимум plugins, остановить вне viewport; сначала проверить, решает ли статичная схема ту же задачу.

**Выбор:** необязательный выразительный акцент для направления A/B, только после нового задания.

## R13. Процесс через четыре фотографии / вертикальную timeline

**Реальные примеры:** [Aceternity Timeline](https://ui.aceternity.com/components/timeline) показывает sticky header и scroll beam; [Slicey](https://www.slicey.ca/) показывает осмысленную последовательность контакта, проверки и получения.

**Технология / лицензия:** Aceternity — React/Tailwind/Motion, ограничение R02; Slicey — сайт-ориентир без выявленной открытой лицензии и без подтверждённого stack. Предлагаемая реализация Filo Fino — собственный HTML ordered list, CSS и собственные фото; стороннего кода не требует.

**Переносимость:** полная для собственной последовательности. Сохранить смысл текущих этапов: приёмка → осмотр → работа → проверка; подтвердить реальные операции с мастером. Не заимствовать обещания и технологию Slicey.

**Mobile:** вертикальный список; каждый этап содержит фото или простой собственный SVG, название и один ясный результат для клиента. Sticky beam и большие sticky-заголовки убрать на коротких экранах. Этапы можно пронумеровать, поскольку это реальная последовательность.

**Производительность:** низкая для статичного списка; средняя с несколькими sticky/scroll-анимациями. Видео по нажатию — poster, controls, ограниченная предзагрузка, без YouTube iframe на первом экране.

**Выбор:** основной способ объяснить качество работы. R12 может быть акцентом, не заменой информации.

## R14. Страница услуги: проблема, доказательство, обращение

**Реальные примеры:** [Slicey Services](https://www.slicey.ca/services), [New Material на One Page Love](https://onepagelove.com/new-material), [официальный WhatsApp click-to-chat](https://faq.whatsapp.com/5913398998672934). New Material опубликован 11.10.2026; в карточке указан Tailwind CSS, но полный stack не установлен. Slicey использует booking, не WhatsApp: переносится структура, а канал — по официальной документации WhatsApp.

**Лицензия:** разрешение копировать код/медиа сайтов Slicey и New Material не установлено. Самостоятельная структура не требует сторонней runtime-лицензии. WhatsApp — внешняя услуга; использование бренда/официального button asset подчиняется его правилам, не MIT. Ничего из медиа или фирменных кнопок не скачивалось.

**Переносимость:** высокая. На обычном HTML показать задачу клиента, подходящую услугу, реальную работу, условия, процесс и контакт. Для новой страницы не нужен SPA или embedded chat widget. Ссылка wa.me с корректным международным номером и URL-encoded текстом — без JS SDK. Реальный номер брать из согласованного источника при реализации, не из примера.

**Mobile:** текстовый CTA на первом экране, повтор после доказательства и условий. Возможная нижняя панель не закрывает контент/фокус и имеет safe-area padding. Номер телефона — альтернативная tel-ссылка. Черновик сообщения указывает услугу; клик не отправляет его автоматически. Нет обязательной формы перед WhatsApp.

**Производительность:** низкая у обычной ссылки; изображения определяют LCP. Chat widgets и сторонние scripts ради запуска диалога не нужны. Нет подтверждения, что этот паттерн увеличит конверсию Filo Fino: это гипотеза для будущего теста.

**Выбор:** основной принцип страниц услуг и оформления контакта во всех трёх направлениях.
